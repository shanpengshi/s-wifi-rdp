# S-WiFi 远程桌面连接助手使用说明

版本：v1.3.0。本文所用 `192.0.2.10`（被控端）和 `192.0.2.20`（控制端）均是演示地址。实际使用请重新查询，并填写自己的地址。

## 一、分清控制端和被控端

控制端是你面前用来操作另一台电脑的设备；被控端是接受远程操作的设备。“本机”指正在运行助手的这台电脑。两端使用同一个 exe，但选择不同角色。

左侧始终是被控电脑 IPv4，右侧始终是控制端 IPv4。控制端模式下自动填右侧；被控端模式下自动填左侧。

## 二、首次准备

在被控电脑的 Windows 设置中打开“系统 → 远程桌面”。确认 Windows 版本支持接受远程桌面连接，且账户有远程登录权限。设置非空账户密码：本地账户的密码与 PIN 不同，远程登录应使用该账户的密码。

被控电脑需要开机、联网且不处于睡眠或休眠状态。可让显示器关闭，但不要让电脑在需要远程访问时自动睡眠。本工具不会修改这些系统设置。

操作参考：[微软远程桌面设置说明](https://support.microsoft.com/zh-cn/windows/experience/connectivity-networking/how-to-use-remote-desktop)、[空密码本地账户的远程登录限制](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/accounts-limit-local-account-use-of-blank-passwords-to-console-logon-only)。

## 三、放置程序

将下载包解压到普通可写文件夹，两台电脑各放一份，双击 `RemoteDesktopHelper.exe`。无需安装 Python，日常运行不需要管理员权限。保留文件夹中的 LICENSE；可以给 exe 创建桌面快捷方式。

## 四、完整连接流程

1. 在控制端选择“本机是控制端”，选择实际使用的网卡，点击“查询并自动填入”，记录右侧控制端地址。
2. 在被控端选择“本机是被控端”，同样查询，记录左侧被控端地址。
3. 如果需要创建按来源 IP 放行的规则，在被控端右侧填入第一步查到的控制端地址，点击“复制控制端放行命令”。
4. 在被控电脑搜索 Windows PowerShell，选择“以管理员身份运行”，粘贴完整命令并执行。成功提示中的地址应与当前控制端一致。
5. 回到控制端，将第二步查到的被控端地址填在左侧，点击“连接远程桌面”。
6. 在 Windows 登录窗口输入被控电脑的账户名与账户密码。用户名可参考被控端“复制本机信息”的 Windows 用户字段，格式通常为 `电脑名\用户名`。

点击连接仅启动 Windows 远程桌面；后续登录由 Windows 完成。被控端模式下连接按钮禁用是正常行为。

## 五、每个按钮的作用

| 项目 | 用途 |
| --- | --- |
| 本机网卡下拉框 | 选择要查询的网卡，注意区分 WLAN、有线网卡和 VPN/虚拟网卡 |
| 查询并自动填入 | 读取本机 IPv4、网关、掩码、MAC，并填入当前角色的地址框 |
| 复制本机信息 | 复制本机网络信息、电脑名、当前 Windows 用户名；被控端还附连接命令 |
| 复制控制端放行命令 | 根据右侧地址生成命令，仅复制，不自动执行 |
| 连接远程桌面 | 使用左侧目标 IPv4 打开系统远程桌面 |

IPv4 输入框只接受四段数字地址，不要填写网址、电脑名称、IPv6 或 `IP:端口`。当前版本按默认远程桌面端口 3389 使用。

## 六、放行命令会修改什么

命令添加或更新 `SWIFI-RDP-TCP` 与 `SWIFI-RDP-UDP` 两条入站规则，端口为 3389，允许的远程来源为右侧输入的控制端 IP。再次执行会将这两条规则的来源更新为新 IP，不会逐次累计旧地址。

命令需要在被控电脑执行。在控制端执行不会替被控电脑完成配置。它不会关闭防火墙或清理其他规则；如果已有更宽的允许规则，添加本工具规则并不意味着系统只接受一个来源 IP。

## 七、IP 变了怎么办

| 变化 | 处理 |
| --- | --- |
| 只有被控端 IP 变了 | 在被控端查询新地址，修改控制端左侧目标 IP |
| 只有控制端 IP 变了 | 查询新地址；若被控端限制旧来源 IP，在被控端更新右侧地址并重新执行放行命令 |
| 两端都变了 | 分别查询，先在被控端更新规则，再在控制端连接新的目标 IP |

助手启动和收到本机网络地址变化通知时会重新查询。它不能远程查找失联电脑，也不会同步两台电脑的地址。若控制端已经无法连接，需要在被控电脑本机或通过已有的其他管理渠道更新规则。

更改输入框不会修改系统实际 IP，也不是固定 IP。校园网地址保留服务需要向网络管理方咨询。

## 八、常见问题

### 0x204：无法连接远程计算机

先确认被控电脑开机、联网、未睡眠；再核对目标 IP、远程桌面开关和当前控制端是否被放行。在控制端 PowerShell 中执行：

```powershell
$targetIp = Read-Host '输入被控电脑当前 IPv4'
Test-NetConnection -ComputerName $targetIp -Port 3389
```

`TcpTestSucceeded : True` 表示当时能连通目标 TCP 3389，不保证账户验证成功；`False` 表示应继续排查地址、服务、防火墙和网络可达性。单独的 Ping 失败不代表远程桌面一定不可用。

被控电脑本机可测试 `Test-NetConnection 127.0.0.1 -Port 3389`。回环测试成功也不能保证外部电脑能够访问。参考：[微软远程桌面连接排查](https://learn.microsoft.com/en-us/troubleshoot/windows-server/remote/remote-desktop-cannot-connect-remote-computer)。

### 0xc07：账户限制，或提示凭据错误

核对被控端本地账户有非空密码，输入的是该账户的真实密码而非 PIN，并有远程登录权限。仍失败时检查账户禁用、登录限制及系统策略。报错代码不能唯一确定原因。

### 查不到 IPv4 或网卡不对

先连接网络并完成必要认证，再查询。程序会过滤回环及 `169.254.*.*` 地址；多网卡时手动选实际联网网卡。选择网卡不会更改 Windows 路由。

### 提示已启动，但没有连上

“已启动”只表示已打开 `mstsc.exe`。是否连接成功以 Windows 远程桌面窗口为准。

### 防火墙命令权限不足

确认在被控电脑的管理员 PowerShell 中执行。组织策略管理的设备可能需要管理员处理。

### 关闭助手后会断开吗

助手只启动系统远程桌面客户端；连接建立后，关闭助手窗口本身不会主动结束 RDP 会话。两端无需为了维持会话一直开着助手。

## 九、设置和隐私

软件目录中的 `last-ip.txt` 保存被控端地址，`helper-settings.ini` 保存角色、控制端地址和网卡。连接、复制放行命令或正常关闭助手时会保存相关设置。无法记住设置时检查目录是否可写。

这些文件可能含真实网络地址，不能上传到公开仓库。对外分享“复制本机信息”的内容前，检查其中的 MAC、电脑名、用户名和地址。助手没有遥测和自动上传功能，不接收账户密码；Windows 自身的凭据保存不属于助手功能。

## 十、网络范围和费用

两台电脑需要网络可达且策略允许 RDP。本工具不提供公网中转、穿透、自动固定 IP 或关机唤醒。离开原局域网或使用手机热点后，不能假设仍能直接连接内网地址。校园网是否计费，以实际规则和账单为准。

窗口可以拖动边缘调整大小，也可以最大化。窄窗口会将两端地址上下排列；高度不足时滚动查看。请将 RemoteDesktopHelper.exe.config 与 exe 保持在同一目录，以启用高 DPI 配置。
